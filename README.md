# 域控台 / Domain Desk 1.5.1

Windows 原生 WPF 的 AD 目录管理客户端。仅保留目录管理，不再提供导航栏、DNS 服务器、文件共享或日志管理页面。远端操作仍逐次确认并写入本地审计日志。

## 启动

- 运行根目录 `Start-DomainDesk.cmd`，或 `artifacts/DomainDesk-win-x64-v1.5.1/DomainDesk.exe`。
- 便携包：`artifacts/DomainDesk-win-x64-v1.5.1.zip`，完整解压后运行。
- Windows 10/11 x64，自包含 .NET 8，无需安装 .NET、RSAT 或 PowerShell 模块。
- 启动为空白、未连接状态；不加载演示数据，不自动连接服务器。点击右上角“连接 AD 域”后才读取实际目录。
- 已连接时可点击同一按钮重新连接或切换服务器。连接失败时保留原连接及其结果；只有新连接通过初始目录查询才替换原连接。
- 新版与旧版发行目录并存，不覆盖或结束正在运行的旧程序。请自行关闭旧窗口并启动新版。

## 界面

- 深青绿色标题区、浅橄榄绿目录树，三栏分别为目录树、当前目录对象列表、对象详情。
- 移除重复的“目录管理”标题、演示横幅、目录标题下的 DN，以及详情中的“对象路径 / DN”。
- “直接所属组”只显示解码后的组名，不显示 `CN=…`、`OU=…`、`DC=…`。不含主组或嵌套组；服务器返回的成员关系仍可能截断。
- 目录树文字和行数能够完整显示时，不显示滚动条；超出可用宽度或高度时自动显示相应滚动条，避免内容无法访问。
- 对象详情内容能够显示完整时隐藏滚动条；长说明、大量组成员或较矮窗口造成溢出时，自动显示纵向滚动条。
- DN 仍用于内部查询、写操作确认、审计与 CSV，不会因界面精简而改变目标定位或权限检查。

## 目录管理

| 对象 / 功能 | 支持内容 |
| --- | --- |
| 目录范围 | 域根、OU、普通容器树；统一列出用户、用户组、计算机；类型筛选、搜索、包含下级目录、统计、CSV 导出 |
| 用户 | 启用 / 停用、解锁、重置密码、下次登录改密、新建用户 |
| 用户组 | 新建全局 / 域本地 / 通用的安全组或通讯组；查看本域直接用户成员；逐个添加 / 移除成员 |
| 计算机 | 预创建停用 AD 计算机账号；编辑描述 / 位置；删除非域控、非关键系统的普通 AD 计算机对象 |
| 连接设置 | 记住 AD 服务器、用户名、身份模式及 TLS 选项；连接默认允许修改，不显示写权限选项；不保存密码，不自动连接 |
| 本地审计 | 写请求先记录再执行；记录结果；不再提供单独的日志页面 |

- 搜索、数量、导出和类型筛选均遵循当前所选目录。默认包含下级目录；取消时只查询直接对象。目录名称筛选仅影响树的显示，不扩大对象查询范围。
- 目录刷新按 GUID 恢复选择和展开状态；目录移动、删除或不可访问时清空旧结果并要求重新选择，不自动切回全域。
- 普通视图隐藏服务器标记为高级视图的整个分支；正常显示 Builtin。域根与 Builtin 不能自动成为新建目标。
- 每次查询最多 5000 项，截断时明确提示；统计与 CSV 只包含当前结果。CSV 保留机器账号真实的 `$` 后缀并防范常见公式注入。
- 新建目标优先使用当前兼容 OU / 容器；无效目标必须由管理员明确选择，不能静默换到其他目录。

## 连接 AD 与安全边界

1. 输入实际域控 FQDN 或 IP，不含 URL、端口或路径。账号支持 `DOMAIN\user` / `user@domain`，密码只在本机连接对话框输入。
2. 默认 LDAPS / TCP 636，要求受信任且名称匹配的域控证书；用 IP 时证书必须含该 IP。不提供忽略证书验证开关。
3. 关闭 TLS 时使用 LDAP / TCP 389 + Negotiate 签名与 SASL 加密，不使用明文 Simple Bind。密码修改最终受域控密码策略、权限和加密强度约束。
4. 连接默认允许修改域对象，不显示“允许修改域对象”选项，也不弹出“启用写操作”确认框。旧配置中的只读选项不会影响新连接；具体写操作仍逐次确认，由域控按账号权限检查，本工具不提升或绕过权限。
5. LDAP 错误 81 表示会话建立失败，不足以认定密码错误。核对真实域控地址、DNS / VPN 解析、389/636 端口与 LDAPS 证书；不要跳过证书验证或降低组织认证策略。
6. 使用 IP 时可能不能获得常规的基于主机名的 Kerberos 验证。组织禁用 NTLM 时应正确配置 DNS / Kerberos / SPN / 信任，本工具不绕过安全策略。

### 写操作

- AD 写操作按 objectGUID 重新定位对象，不因界面只显示名称而改用名称定位。请求日志落盘失败时拒绝提交写操作；服务器执行最终授权检查。
- 解锁将 `lockoutTime` 清零，不依赖可能延迟的锁定状态显示。`lastLogonTimestamp` 可能延迟，不能视为实时登录状态。
- 新建用户先创建停用对象、再设置密码 / 下次改密、最后按选择启用。后续阶段失败可能留下已创建对象；先刷新核实，不自动删除、回滚或重复提交。
- 新建计算机使用兼容的 1–15 位 ASCII 字母 / 数字 / 连字符名称，首尾为字母或数字，不能为纯数字；界面不接受 `$` 或域名后缀，内部只添加一次 `$`。
- 计算机以 `userAccountControl=4098` 停用预创建，不设置可预测机器密码、免密 / 委派标志，不创建 SPN 或 DNS，不执行远端加域或重命名。账号重用由服务器加域加固策略决定。
- 新建组默认全局安全组；创建空组，不自动添加成员或授予资源权限。通讯组不自动配置邮件服务。组作用域最终由域功能级别和服务器授权决定。
- 计算机编辑仅修改 AD 描述和位置，不改 CN / sAMAccountName / SPN / DNS。删除需输入计算机名确认，仅作普通非递归删除；拒绝域控、RODC 和关键系统对象。
- 组成员操作仅修改所选用户的直接成员关系，不替换整组成员列表、不删除用户。特权组成员变更可能授予或撤销权限。
- 写请求超时、断网时可能已经生效，应先刷新核实，禁止盲目重试。服务器成功但刷新失败时明确提示不要重复提交。

### 本地文件

- `%LOCALAPPDATA%\DomainDesk\connections.json`：非密码连接配置；损坏时提示并使用默认值。原有其他模块配置不作为 AD 连接使用，不主动删除用户配置。
- `%LOCALAPPDATA%\DomainDesk\audit.jsonl`：请求及结果审计；保留服务器、操作者、对象 DN 与结果。普通本地文件不防篡改、不自动轮转，应配合服务器审计与备份。
- 密码不写入配置、日志、命令行或外部脚本。EXE 未商业代码签名，生产分发前应自行审批、扫描和签名。

## GitHub Actions 与 Releases

仓库只提交源码、测试、构建脚本和必要图标资源。`artifacts/`、`.tools/`、`bin/`、`obj/`、缓存和便携包均不进入 Git；发行文件由 GitHub Actions 构建后上传。

- `main` 分支推送至 GitHub 后，自动构建、运行本地夹具测试、发布 Windows x64 自包含便携包，并检查 EXE 能否启动和正常退出。
- 主分支构建的 ZIP 和 SHA256 校验文件保存在 Actions 的 Artifacts 中，保留 14 天；也可在 Actions 页面手动运行 `Windows Portable`。
- 推送与项目版本完全一致的标签（如 `v1.5.1`）后，自动创建 GitHub Release，上传便携 ZIP 和 `.zip.sha256`。先上传至草稿，全部成功后才公开；重跑不会覆盖已公开 Release。
- 原仓库自动镜像至 GitHub 时，须同时同步版本标签，并在 GitHub 仓库启用 Actions。工作流使用内置 `GITHUB_TOKEN`，不需要在源码中配置令牌。

发布当前版本：

```powershell
git push origin main
git tag -a v1.5.1 -m "Domain Desk 1.5.1"
git push origin v1.5.1
```

后续发布先修改 `DomainDesk/DomainDesk.csproj` 的 `Version`，并同步界面版本与便携启动检查中的版本文本，再创建对应新标签；标签与项目版本不一致时工作流会停止，避免错误标记发行包。也可在 Actions 手动选择已有版本标签重新运行发布。
